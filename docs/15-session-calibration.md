# 单账号 15 路标定报告

> 项目：`codex-prism` / Prism 反代网关单账号并发标定
> 日期：2026-10-02
> 账号池：1 个可用（CPA，`plan=pro`）

## 一、结论

| | 数值 |
|---|---|
| **单账号健康状态下的天花板** | **12 / 15（80%）** |
| 达成条件 | 串行平滑放行（相邻请求间隔 **~12s**）|
| 失败形态 | 「触发配额 → 短暂冷却 → 恢复放行」|
| **是否存在硬性固定并发上限** | ❌ **不存在**（已用判别实验推翻）|

**「15 路不同会话并发」的正确读法**：15 路**会话可同时在线**（各占独立项目/材料槽），
但**上游调用需按 ~12s 间隔平滑放行**。这是单账号的真实速率配额约束。

**要 15 路同刻在飞** → 需**多账号**。当前仅有 1 个可用账号，故多账号上限无法验证。

## 三、判别实验：瓶颈是「突发」不是「上限」

```
串行 10 次（间隔 6s，仅 1 路在飞）：
  #1 ✓ #2 ✓ #3 ✓ #4 ✓ #5 ✓ #6 ✓ #7 ✓   ← 连续 7 次成功
  #8 ✗   #9 ✓
```
若为「每窗口固定 N 次」的硬配额，串行不可能连过 7 次。
→ **上游拦的是突发（burst）**，平滑放行即可大幅缓解。

## 四、⚠️ 两个曾污染实验的因素（必须记住）

### 4.1 `PRISM_SENTINEL_URL` 缺失（本地配置坑）

| 配置 | 行为 |
|---|---|
| `PRISM_SENTINEL_URL=http://127.0.0.1:8791` | ✅ 直连常驻 daemon（铸造 ~0.6s）|
| **未配置** | ❌ 退回「每请求现起 node runner」→ **每请求重载 5s+** |

后果：15 路并发下 node 风暴 + 全超时，报
`取 sentinel 失败: 启动 node runner 失败: context deadline exceeded`
—— **看起来像上游问题，实为本地配置缺失**（曾据此得到无效的 0/15）。

> ✅ 已在实验脚本加**前置预检门**：`/healthz` 须 `ok:true` 且 `/token` 须 200，否则中止。

### 4.2 账号**累积退化**：测速本身在压坏它

延迟随累计调用**单调上升**：`10s → 90s → 243s → 400-600s`；
v6 失败形态变成 `status: context deadline exceeded`（撞 10 分钟轮询上限），不再是 403。
→ **「越测越差」不是配置问题，是账号被压坏了**。

> 📌 标定实验必须**串行进行 + 轮次间充分冷却**。v5 的 12/15 才是干净读数。

## 五、最终工艺（已落地为 env）

| env | 建议值 | 作用 |
|---|---|---|
| `PRISM_MIN_GAP_MS` | **12000** | ⭐ 平滑放行（最关键）|
| `PRISM_SLOT_ATTEMPTS` | **1** | ⭐ 关掉换槽重试（放大器）|
| `PRISM_MAX_INFLIGHT` | 1–3 | 在飞闸门（辅助）|
| `PRISM_COOLDOWN_MS` | 8000–20000 | 账号级熔断递增退避 |
| `PRISM_MATERIAL_TTL_MS` | ≥ 一轮总时长 | 防后段材料过期 |
| `PRISM_SENTINEL_URL` | `http://127.0.0.1:8791` | ⚠️ **必设** |
| `PRISM_TLS_PROFILE` | 1（默认）| 注入 Chrome TLS 指纹 |
